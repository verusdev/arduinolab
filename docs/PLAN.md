# План: настоящая мехрука и 4-колёсная машинка

## Решения (согласованы с пользователем)

1. **Машинка** — 4 колеса, на каждом свой мотор: по 3 пина на мотор (2 направления + ШИМ) = 12 пинов,
   плюс **два** дальномера (спереди и сзади). Старая 2-моторная машинка заменяется.
2. **Рука — оба варианта:**
   - `Robot Arm` — один компонент-конструктор: число сегментов (2–6), у каждого сустава
     свой серво (галочка) и свой пин; неоснащённый сустав держит заданный угол.
   - Сборка **из деталей**: `Arm Base` + `Arm Link` + `Arm Gripper` + обычный `Servo`.
     Звенья щёлкают друг к другу, серво вставляется в нужный сустав и вращает всё, что выше.
3. Старые простые сборки заменяются новыми, уроки обновляются.

## Ключевые технические решения

- **Кинематика руки — чистая функция** в `lib/engine/robotics.dart` (без Flutter), тестируется напрямую.
- **Сочленение деталей**: у каждой детали есть `pivot` (точка вращения) и `socket` (куда
  втыкается следующая). Ребёнок втыкается pivot'ом в socket родителя; угол ребёнка =
  угол родителя + (родитель — серво ? его угол : 0). Это даёт честную прямую кинематику.
- **Поза «запекается»** в `x/y/rotation` деталей (`ArmAssembly.bake`), поэтому провода,
  выделение и hit-test работают без изменений.
- **Серво — сустав** и единственная деталь с пинами, поэтому его `pivot` = центр
  (совпадает с тем, как `PlacedComponent.pinPosition` вращает пины).
- **Вращение о pivot**: у деталей руки `Transform.rotate(alignment:)` берётся из `ArmMount`,
  у остальных компонентов остаётся центр.
- Угол серво-сустава: `servo write 0..180` → поворот −90..+90 (`servoJointDegrees`).
- Пины «липнут» на отпускании перетаскивания; при начале перетаскивания деталь
  отсоединяется. Один socket — один ребёнок.
- Машинка, как и раньше, шагает по **виртуальному** времени программы.
